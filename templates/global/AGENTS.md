## How I work

- Read before you write. Prefer editing an existing file over creating a new one.
- Match the surrounding code: naming, comment density, error handling, test style.
- Small, reviewable changes. No refactors I did not ask for.
- Say what you actually did, including what failed or was skipped.

## Guardrails

- Ask before anything destructive or outward-facing: force-push, migrations,
  deploys, deletes, publishing.
- Never commit secrets. Never read `.env` unless I ask.
- Don't add dependencies without saying why the standard library won't do.
